# Armed-extra hint remaps in light mode

Written against: bfc5317

## Evidence chain

- Surface: `#/score/:id`, the run pad, after tapping Wide / No ball / Bye / Leg bye (the hint line "Wide armed — tap the runs the batters ran…").
- Problem: the hint is `text-amber-200/90`; in light mode it renders pale yellow (`hsla(48,97%,77%,.9)`) on a white card.
- Design evidence: `src/css/input.css` `@layer utilities` comment — accent text is remapped to a readable shade per exact class, generated by `scripts/gen-light-accents.mjs`; `DESIGN.md` → Colors: "Write accent text as a plain `text-<hue>-<shade>` class with no opacity modifier and no arbitrary value, or it will not remap"; `src/css/app.css` has `.text-amber-200\/90{…}` with no `html[data-theme='light']` override, while `.text-amber-200` has `html[data-theme='light'] .text-amber-200{color:#92400e}`.
- Owner: `src/js/views/score.js:317`.
- Scope and affected surfaces: that one line; a repository-wide search finds no other opacity-modified accent text class.
- Uncertainty: none.

## Design decision

Use the plain accent class so the generated light-mode remap applies. The 90% opacity was a dark-theme softening that the token system has no way to carry into light mode.

## Reuse

- `text-amber-200` — the plain form already used for notices at `src/js/views/score.js:691` and `:524`.
- Exemplar: `src/js/views/score.js:691`.
